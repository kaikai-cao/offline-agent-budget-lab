# E0.2 — Local budget ledger and atomic consumption

**Status:** implementation package; results must be generated locally.  
**Scope:** one process, one `LocalBudgetLedger` instance per lease, in-memory state.

## State accounting

For one lease with allocation `b`, local records are partitioned into four states:

- `reserved`: capacity has been atomically held before an external operation;
- `committed`: the operation is known to have completed;
- `aborted`: the caller knows the external operation did not take effect; capacity is released;
- `indeterminate`: the external outcome is unknown; capacity remains occupied conservatively.

The ledger enforces:

`committed_budget + reserved_budget + indeterminate_budget <= allocated_budget`

and:

`available_budget = allocated_budget - committed_budget - reserved_budget - indeterminate_budget`.

`abort()` must not be used merely because a client timed out. An ambiguous result must be marked `indeterminate`, otherwise the same capacity could be reused while the original operation may already have taken effect.

## API

- `LocalBudgetLedger(lease, issuer_public_key_bytes, clock=...)`
- `reserve(operation_id, cost=1)`
- `commit(operation_id)`
- `abort(operation_id)`
- `mark_indeterminate(operation_id)`
- `get_operation(operation_id)`
- `operations()`
- `snapshot`

Repeated identical terminal transitions (`commit` after `commit`, `abort` after `abort`, or `mark_indeterminate` after `mark_indeterminate`) are idempotent. Incompatible terminal transitions are rejected. Operation IDs remain consumed even after abort and cannot be reused in that ledger instance.

## Concurrency guarantee

A single `threading.Lock` protects all state transitions of one ledger object. This should make concurrent threads sharing the same object contend on one authoritative in-memory state. It does **not** coordinate two objects, two processes, hosts, or copied/restored state.

## Explicit limitations

- No persistence or crash recovery.
- No cross-process or cross-host atomicity.
- No anti-rollback protection.
- No tool execution, execution receipts, receipt hash chain, or final reconciliation.
- The transition from `reserved` to `committed` is not atomic with an external tool's side effect. A crash between those actions can produce ambiguity; callers must conservatively mark uncertain outcomes as `indeterminate` when the process can still recover, but this package does not provide crash-durable recovery.
- The injected clock is used for lease validity checks; it is not a trusted time source.

## Acceptance tests

`tests/test_ledger.py` checks signature and lease-time validation, budget reservation, duplicate operation IDs, state transitions, conservative indeterminate handling, operation sequencing, and concurrent reservation using multiple threads.
