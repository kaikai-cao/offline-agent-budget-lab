# E4.6 TPM 2.0 Read-only Property Probe v0.1

**Scope:** Query TPM properties only. No NV data is read and no NV index is created, written, incremented, or deleted.

## Why this stage exists

E4.5 confirmed 16 existing NV indices and decoded four of them as `TPM_NT_COUNTER`. One of those four has `TPMA_NV_ORDERLY=SET`; the other three have it clear. Before considering a dedicated test index, collect the TPM's advertised NV capacity and pacing properties.

## Properties queried

| Property | ID | Meaning |
|---|---:|---|
| `TPM_PT_NV_COUNTERS_MAX` | `0x00000116` | Maximum number of NV indices allowed to have `TPM_NT_COUNTER` |
| `TPM_PT_NV_INDEX_MAX` | `0x00000117` | Maximum data size of one NV index (not the number of indexes) |
| `TPM_PT_ORDERLY_COUNT` | `0x0000011D` | `MAX_ORDERLY_COUNT` parameter for orderly counters |
| `TPM_PT_NV_BUFFER_MAX` | `0x0000012C` | Maximum data size in one NV read/write/extend/certify command |
| `TPM_PT_HR_NV_INDEX` | `0x00000202` | Current number of defined NV indices |
| `TPM_PT_NV_COUNTERS` | `0x0000020A` | Current number of defined counter indices |
| `TPM_PT_NV_COUNTERS_AVAIL` | `0x0000020B` | Estimate of additional counters with `TPMA_NV_ORDERLY=SET`; it is **not** a general free-counter count |
| `TPM_PT_NV_WRITE_RECOVERY` | `0x00000212` | Approximate delay before the TPM accepts another NV-modifying command |

These definitions are from the published TCG TPM 2.0 Library Part 2, Version 185 (March 12, 2026), Tables 27 and 28.

## Important semantic distinction

`TPMA_NV_ORDERLY=SET` means the index state is saved to NV during orderly shutdown. When `TPMA_NV_ORDERLY=CLEAR`, the TPM is required to make a successful NV update persistent when the command completes. This distinction matters for a counter intended to survive abrupt power loss. The queried `TPM_PT_NV_COUNTERS_AVAIL` specifically estimates additional **ORDERLY** counters and must not be misread as the total availability for non-ORDERLY counters.

## Interpretation rules

- Check both the TBS return code and the TPM response code for each property query.
- `Status=OK` means the exact requested property ID was returned.
- `NEXT_PROPERTY_RETURNED_NOT_EXACT` does not count as support for the requested property.
- A zero or absent `TPM_PT_NV_COUNTERS_AVAIL` does not by itself prove that no non-ORDERLY counter can be defined.
- These are capability/property values reported by the TPM, not a successful trial of `TPM2_NV_DefineSpace` or `TPM2_NV_Increment`.
- Do not infer authorization policy, NV ownership, or a safe free handle from these properties.

## Safety boundary

This probe sends only `TPM2_GetCapability(TPM_CAP_TPM_PROPERTIES)`. It must not be extended to send `TPM2_NV_DefineSpace`, `TPM2_NV_Increment`, `TPM2_NV_Write`, `TPM2_NV_UndefineSpace`, or any other NV-mutating command in this stage.
