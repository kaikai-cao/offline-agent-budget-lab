# E4.5 — TPM NV Public Metadata Read-Only Inspection v0.1

## Purpose

Inspect the public metadata for the 16 NV handles returned by the user's E4.4 `TPM_CAP_HANDLES` query. This is a preparation step before deciding whether a dedicated test NV index can safely be allocated.

## Command sent

Only `TPM2_NV_ReadPublic` (`TPM_CC_NV_ReadPublic = 0x00000169`) is sent, once per observed handle.

The script does **not** send:

- `TPM2_NV_Read`
- `TPM2_NV_Write`
- `TPM2_NV_Increment`
- `TPM2_NV_DefineSpace`
- `TPM2_NV_UndefineSpace`
- `TPM2_Clear`

It does not read the contents stored at the NV indices. It reads public metadata: `nvIndex`, `nameAlg`, `TPMA_NV` attributes, `authPolicy` digest, `dataSize`, and the computed TPM Name returned by the TPM.

## Observed handles (from E4.4)

```text
0x01400001 0x01400002 0x0140000A
0x01410001 0x01410002 0x01410003
0x01800100 0x01810008 0x01820002
0x01880001 0x01880011
0x01C00002 0x01C00016
0x01C10102 0x01C10104 0x01C101C0
```

## Interpretation limits

- `TPM_CAP_COMMANDS` advertising a command means the TPM reports implementation support. It does not establish that Windows/TBS policy permits the command, nor that a particular NV index authorizes the caller.
- `TPM2_NV_ReadPublic` success does not authorize `TPM2_NV_Read` or a write command for that index.
- `TPM2_NV_ReadPublic` returns public metadata only. Do not infer stored values from `dataSize` or `authPolicy`.
- Handle ranges are conventional namespace allocations in the TCG registry. A handle range is not enough to decide whether an index is safe to delete, redefine, or use. Do not change any discovered index.
- The script is a read-only probe with respect to NV storage, but it does submit TPM commands and creates/closes a transient TBS context.

## What to send back

Return the complete output, including each handle's TBS result, TPM response code, `NameAlg`, raw `Attributes`, `DataSize`, `AuthPolicyDigest`, and `NvName`.

## Safety boundary

Do not run `TPM2_NV_DefineSpace`, `TPM2_NV_UndefineSpace`, `TPM2_NV_Write`, `TPM2_NV_Increment`, or `TPM2_Clear` during this phase. A future mutating experiment requires a separately reviewed index allocation plan, explicit authorization policy, recovery/cleanup plan, and user confirmation.
