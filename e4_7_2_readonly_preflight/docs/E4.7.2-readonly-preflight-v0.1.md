# E4.7.2 — Owner NV Counter 只读预检

**状态：** 只读预检任务；不是写入授权，也不是 NV 空间可用性证明。

## 1. 目标

在不修改 TPM NV 状态的前提下，检查候选 Owner NV Handle `0x01BFFFFE` 是否已定义，并确认 E4.5 记录的 16 个现有 NV Index 的 TPM Name 未发生变化。同时读取 `TPM_PT_PERMANENT` 与 `TPM_PT_STARTUP_CLEAR`，确定 Owner/Storage hierarchy 的必要状态。

## 2. 依据与 Handle 范围

TCG《Registry of Reserved TPM 2.0 Handles and Localities》v1.2 Revision 1.00 将 `0x01800000–0x01BFFFFF` 作为由 Owner 自行分配的 NV Handle 区间。该注册表明确说明它不分配 TPM 内部实际 NV 空间；实际是否已定义必须查询设备本身。见 TCG 注册表第 2.2.2 节，尤其 Table 2 与 2.2.2.1。

候选 `0x01BFFFFE` 仅作为本轮预检目标；不得因它位于范围内就推断它一定空闲或适合生产使用。

## 3. 冻结的候选 NV Public Area

| 字段 | 候选值 |
|---|---|
| nvIndex | `0x01BFFFFE` |
| nameAlg | SHA-256 (`0x000B`) |
| dataSize | 8 |
| attributes | `0x00040014` |
| TPMA_NV type | COUNTER (`TPM_NT=1`) |
| AUTHREAD | SET |
| AUTHWRITE | SET |
| ORDERLY | CLEAR |
| POLICY_DELETE | CLEAR |
| PLATFORMCREATE | CLEAR |
| authPolicy | empty |

掩码 `0x00040014` = `TPMA_NV_AUTHREAD (0x00040000)` + `TPMA_NV_AUTHWRITE (0x00000004)` + `TPM_NT_COUNTER (0x00000010)`。`ORDERLY`、`POLICY_DELETE`、`PLATFORMCREATE` 均 CLEAR。

Owner NV handle range 与 Index Public Area 中的 `PLATFORMCREATE` 是相关但不同概念：候选使用 Owner NV 区间，且候选 Public Area 计划令 `PLATFORMCREATE=CLEAR`，这表示创建/管理使用 Owner hierarchy。

## 4. 只读命令

1. `TPM2_GetCapability(TPM_CAP_TPM_PROPERTIES)`：读取 `TPM_PT_PERMANENT (0x200)` 与 `TPM_PT_STARTUP_CLEAR (0x201)`。
2. `TPM2_GetCapability(TPM_CAP_HANDLES)`：枚举当前 NV Handle。
3. `TPM2_NV_ReadPublic`：重新读取 E4.5 的 16 个索引，并检查其 Name；同时查询候选 Handle。

候选未定义的预期 TPM 错误为带首个 handle 参数标识的 `TPM_RC_HANDLE`（通常为 `0x0000018B`）。只有在 TBS 调用成功、TPM 响应码恰为该值、候选也不在 Capability Handles 清单中、且 `shEnable=1` 时，才标记为 `UNDEFINED_AT_PROBE_TIME`。任何其他错误均为 `INCONCLUSIVE`，不得解释为空闲。

## 5. 关键状态位

- `TPMA_PERMANENT.ownerAuthSet`：bit 0。只说明 Owner auth 是否已设置；不暴露 auth 值。
- `TPMA_PERMANENT.inLockout`：bit 9。
- `TPMA_STARTUP_CLEAR.shEnable`：bit 1。必须为 SET，Owner hierarchy 授权及以 Owner authorization 定义的 NV indices 才能使用。
- `TPMA_STARTUP_CLEAR.phEnable`：bit 0，仅作记录。
- `TPMA_STARTUP_CLEAR.phEnableNV`：bit 3，仅作记录；候选不是 Platform-created index。

## 6. 只读预检 PASS 的含义

`ReadOnlyPreflightPass=True` 仅在以下条件全部满足时成立：

- E4.5 记录的 16 个 TPM Name 全部匹配；
- 候选 Handle 未列入当前 NV handles；
- 候选 `NV_ReadPublic` 返回预期未定义句柄响应；
- `shEnable=1`；
- `inLockout=0`。

这不证明：

- TPM 对 `ORDERLY=CLEAR` Counter 一定还有足够 NV 空间；
- `NV_DefineSpace` 一定成功；
- OwnerAuth 值已知或可用；
- 该 Handle 在未来仍空闲；
- Counter 可抵御拥有 Owner authorization 的恶意主体删除重建；
- TPM 单调计数器与外部工具效果构成原子事务。

## 7. 停止条件

若基线 Name 不匹配、候选已占用、TBS/TPM 返回非预期错误、`shEnable=0` 或 `inLockout=1`，停止，不尝试换用相邻 Handle，不执行任何写操作。

即使只读预检 PASS，也必须单独审查 OwnerAuth 的实际可用性、受控写入/恢复/清理方案，并另行获得用户明确同意，才可进入 DefineSpace 实验。

## 8. 明确禁止

本阶段不执行：`TPM2_NV_DefineSpace`、`TPM2_NV_Increment`、`TPM2_NV_Write`、`TPM2_NV_Read`、`TPM2_NV_UndefineSpace`、`TPM2_Clear`、`TPM2_HierarchyControl`。
