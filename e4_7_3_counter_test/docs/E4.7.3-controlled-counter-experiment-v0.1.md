# E4.7.3：受控 TPM NV Counter 持久性实验 v0.1

**状态：** 待用户本机执行；不是实测结果，也不是生产安全实现规范。  
**目标：** 在已确认的 Nuvoton NPCT75x TPM 2.0 上，创建一个专用 NV Counter，成功递增一次，正常重启 Windows 后读取并比较精确计数值，最后只删除本实验创建的索引。  
**测试 Handle：** `0x01BFFFFE`  
**依据：** 用户 E4.1–E4.7.2 本地输出；TCG TPM 2.0 Library Part 2 v185 和 Part 3；Microsoft TBS API 文档。

## 1. 本次实验能证明什么

在本机该 TPM、当前固件和当前 Windows/TBS 路径下，测试一个 `TPM_NT_COUNTER`、`TPMA_NV_ORDERLY=CLEAR` 的 NV Index：

1. TPM 是否接受指定 public area；
2. `TPM2_NV_Increment` 是否成功返回；
3. 命令成功后读取到的计数值，在一次正常 Windows 重启后是否保持完全一致；
4. 测试索引是否能通过 Owner hierarchy 授权被删除；
5. E4.5 中原有 16 个 NV Name 是否保持不变。

本实验**不能**证明：

- 抵抗拥有 TPM Owner 授权或管理员权限的恶意软件；
- 抵抗 TPM 固件、芯片或供应链被攻破；
- NV Counter 与外部数据库/工具操作具有原子性；
- 多台设备间的全局唯一性；
- 真实业务部署中的寿命、耐久性或长期性能。

## 2. 为什么第一次递增后的计数值不一定是 1

TCG 已发布的 Part 1 Revision 01.83 §37.2.6.3 规定：新建 NV Counter 初始没有值且 `TPMA_NV_WRITTEN` 为 CLEAR；第一次 `TPM2_NV_Increment` 会初始化计数值，使其高于该 TPM 上具有相同 Name 的 Counter 在该 TPM 生命周期内曾有过的值，然后设置 `TPMA_NV_WRITTEN`。因此，实验不能假定新建 Counter 从 0 开始，也不能假定第一次 `NV_Increment` 后值必为 1。

本实验采用：

- 创建索引；
- 成功执行一次 `NV_Increment`；
- 立即读取并记录实际值 `C1`；
- 重启后读取 `C2`；
- 验收条件为 `C2 == C1`。

定义后但尚未执行首次递增时，TPM 会清除该索引的 `TPMA_NV_WRITTEN`；此时读操作会因索引尚未初始化而返回 `TPM_RC_NV_UNINITIALIZED`。所以脚本不会尝试在首次递增前读取 Counter。第一次递增会把 `TPMA_NV_WRITTEN` 置位，而该位属于 NV Public Area 的 attributes；因此 NV Name 也会随之变化。脚本分别计算 WRITTEN CLEAR 和 WRITTEN SET 两个预期 Name，并在每个阶段按当前状态核对，不能把创建后的 Name 错误地沿用到递增后。

删除 Counter 不会清除 TPM 自制造以来 Counter 值的高水位历史；以后重新定义 Counter 时，其初始值会继续高于既往值。这是规范的单调性设计，不是残留错误。

## 3. 冻结的 NV Public 配置

| 字段 | 值 |
|---|---|
| `nvIndex` | `0x01BFFFFE` |
| `nameAlg` | SHA-256 (`0x000B`) |
| `attributes` | `0x00040014` |
| `TPM_NT` | Counter (`0x1`) |
| `TPMA_NV_AUTHWRITE` | SET |
| `TPMA_NV_AUTHREAD` | SET |
| `TPMA_NV_ORDERLY` | CLEAR |
| `TPMA_NV_POLICY_DELETE` | CLEAR |
| `TPMA_NV_PLATFORMCREATE` | CLEAR |
| `authPolicy` | Empty Buffer |
| `dataSize` | 8 bytes |

`0x00040014 = 0x00040000 (AUTHREAD) | 0x00000004 (AUTHWRITE) | 0x00000010 (TPM_NT_COUNTER)`。

索引 authValue 为随机 32 字节，由 SHA-256 NameAlg 限定；脚本通过 Windows DPAPI（当前 Windows 用户范围）保护并存放在 `%LOCALAPPDATA%`，不会打印在控制台。所有阶段必须由同一 Windows 用户、在同一台机器上运行。

## 4. Owner hierarchy 授权假设

E4.7.2 观察到 `ownerAuthSet=False`。TCG Part 2 v185 定义该位为：自上一次 `TPM2_Clear` 后没有执行过 Owner `TPM2_HierarchyChangeAuth`。TCG Part 3 规定 `TPM2_Clear` 会将 `ownerAuth` 设为 Empty Buffer。因此脚本仅在 `ownerAuthSet=False`、`shEnable=True`、`inLockout=False` 且 `readOnly=False` 时，才使用 EmptyAuth 提交 `NV_DefineSpace` 和 `NV_UndefineSpace`。

该判断是基于 TPM 永久状态位的标准语义，不是读取 OwnerAuth 密钥本身。若任何前置条件不符合，脚本会失败关闭；不尝试猜测 OwnerAuth，不执行 `TPM2_HierarchyChangeAuth`，也不通过清除 TPM 来恢复。

## 5. 操作序列与明确写入点

### Phase 0：离线自检

`00-offline-marshalling-self-test.ps1` 只编译 C# helper 并验证命令字节布局，不创建 TBS context、不发送 TPM 命令。

### Phase 1：创建与单次递增

`01-create-and-increment.ps1`：

1. 要求管理员 PowerShell；
2. 使用 `TPM2_GetCapability(TPM_CAP_COMMANDS)` 逐项确认 NV_DefineSpace、NV_Increment、NV_Read、NV_ReadPublic、NV_UndefineSpace 被 TPM 声明支持。这不是 Windows/TBS 允许列表保证，实际命令返回仍单独检查；
3. 检查 `ownerAuthSet=False`、`inLockout=False`、`shEnable=True`、`phEnableNV=True`、`readOnly=False`；
4. 对比 E4.5 原有 16 个 NV Name；
5. 确认 `TPM_PT_HR_NV_INDEX=16`、`TPM_PT_NV_COUNTERS=4`；
6. 确认候选 Handle 不在 `TPM_CAP_HANDLES` 中，且 `NV_ReadPublic` 返回 `TPM_RC_HANDLE (0x8B)`；
7. 要求输入 `CREATE-COUNTER 0x01BFFFFE`；
8. 生成随机 index authValue，并先以 DPAPI 保护；
9. 发送一次 `TPM2_NV_DefineSpace`；
10. 读取 public area，核对 Name、attributes、dataSize；
11. 要求输入 `INCREMENT-ONCE 0x01BFFFFE`；
12. 在发送递增命令前持久化 `IncrementAttempted=true`，然后只发送一次 `TPM2_NV_Increment`；
13. 只有 TBS 与 TPM 均返回成功，才标记命令成功；随后确认 `TPMA_NV_WRITTEN=SET`，核对 WRITTEN SET 状态下变化后的 Name，再执行 `TPM2_NV_Read` 记录实际 `C1`。

脚本在发送递增命令前先写入 attempt marker。若脚本中断或返回不确定状态，严禁重新执行 Phase 1 来“重试递增”。如成功响应后未能记录计数值，可在重启前运行 `01b-capture-value-before-reboot.ps1`，它只读取当前值，不会递增。若递增结果不确定，该恢复脚本先检查 WRITTEN 位；若仍为 CLEAR 且 `NV_Read` 返回 `TPM_RC_NV_UNINITIALIZED`，会记录“首次递增未生效”，允许清理未初始化的测试索引，但绝不自动重试递增。

### Phase 2：重启验证

正常重启 Windows（Start → Power → Restart）。不要执行 TPM Clear、不要改 BIOS/TPM 配置，也不要切换 Windows 用户。

`02-verify-after-reboot.ps1` 要求 `Win32_OperatingSystem.LastBootUpTime` 晚于 Phase 1 记录的启动时间，然后：

1. 验证候选索引 Name 和 public attributes；
2. 使用 DPAPI 恢复 index authValue；
3. 读取 Counter 值 `C2`；
4. 精确比较 `C2 == C1`。

只有递增命令明确成功且值完全相同，才报告 `PersistenceVerified`。若递增命令响应不确定，即使前后值相同，也会单独标记为“观察到持久性，但递增命令结果不确定”，不计为干净的成功实验。

### Phase 3：清理

`03-cleanup.ps1` 只接受已验证或明确记录为未递增/首次递增未生效的状态；重新检查候选 Name（按 WRITTEN 状态区分）、原有 16 个 Name 和计数值，然后要求输入 `DELETE-OWN-TEST-INDEX 0x01BFFFFE`。在发送前先持久化 `UndefineAttempted` 标记，之后只发送针对候选 Handle 的 `TPM2_NV_UndefineSpace`（Owner hierarchy / EmptyAuth）。若删除命令结果不确定，禁止直接重跑清理脚本；先用只读 finalizer 检查候选是否已不存在。若候选仍存在，保留状态文件并停止，检查实际响应后再决定是否重新授权一次删除。

删除后验证：

- 候选 Handle 不再存在；
- 原有 16 个 NV Name 全部匹配 E4.5 基线；
- `TPM_PT_HR_NV_INDEX=16`；
- `TPM_PT_NV_COUNTERS=4`。

只有所有检查通过，才删除本地 DPAPI auth/state 文件并保留 cleanup report。若 Undefine 命令已成功但脚本在确认删除后中断，可使用 `04-finalize-if-candidate-absent.ps1`：它只读确认候选 Handle 已不存在、原有 16 个 Name 不变且 NV 数量恢复为 16/4，然后在额外确认后删除本地 DPAPI/state 文件；该恢复脚本不发送 TPM 写命令。

## 6. 失败语义与停止条件

| 情况 | 处理 |
|---|---|
| 候选 Handle 已存在 | 立即停止，不覆盖、不复用 |
| 原有 16 个 Name 任一变化 | 立即停止，不写入 |
| `ownerAuthSet=True` 或层级禁用或 Lockout 或 ReadOnly | 立即停止，不猜授权、不修改层级 |
| `NV_DefineSpace` 返回 `TPM_RC_NV_SPACE` | 停止；不换用现有 Handle、不循环重试 |
| `NV_DefineSpace` / `NV_Increment` TBS 或 TPM 返回非零 | 保存状态；不盲目重试；先只读检查候选 Name 和状态 |
| `NV_Increment` 已尝试但结果不确定 | 不再递增；需要时只运行 `01b` 读取当前值 |
| 重启后值不一致 | 保留索引和本地状态，不删除，不递增 |
| OwnerAuth 授权失败 | 停止；不尝试 `TPM_Clear`、不修改 OwnerAuth、不删除其他索引 |
| 清理失败或 Undefine 结果不确定 | 保留 DPAPI/state 文件和 Handle/Name 记录；不直接重跑删除命令，先只读检查候选是否已不存在 |

**严禁操作：** `TPM_Clear` / `Clear-Tpm`、`Initialize-Tpm`、删除现有 16 个索引、修改 OwnerAuth、修改 PlatformAuth、重复 NV_Increment、对候选 Handle 以外的索引执行任何写命令。

## 8. 规范与 API 依据

- TCG, *Trusted Platform Module Library Part 1: Architecture*, Revision 01.83, §16、§37.2.6.3。NV Name 会随 public attributes 改变；Counter 首次递增时 `TPMA_NV_WRITTEN` 从 CLEAR 变为 SET，Name 随之改变；首次计数值高于同一 Name 的 Counter 在该 TPM 生命周期内曾出现过的值；ORDERLY=CLEAR 的更新写入 NV。
- TCG, *Trusted Platform Module Library Part 3: Commands*, §31.2、§31.3、§31.4、§31.6、§31.8、§31.13。NV Counter 为 8 字节单调计数值，只能通过 `TPM2_NV_Increment` 修改；NV DefineSpace 可能因 NV 存储不足返回 `TPM_RC_NV_SPACE`；NV Read 对 Counter 建议 offset=0。
- TCG, *Trusted Platform Module Library Part 2: Structures*, v185, §8.6–§8.7。`ownerAuthSet`、`inLockout`、`shEnable`、`phEnableNV` 和 `readOnly` 的位语义。
- Microsoft Learn, `Tbsip_Submit_Command`: TBS 成功与 TPM response code 成功必须分别检查；Locality 0 和 normal priority 200 为支持值。
- Microsoft Learn, `TBS_CONTEXT_PARAMS2`: `version=TPM_VERSION_20` 且 `includeTpm20=1`。
