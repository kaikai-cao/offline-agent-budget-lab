# E4.7.3 Recovery: DefineSpace succeeded, PowerShell validation failed

## Observed situation

The first E4.7.3 run printed `Sending TPM2_NV_DefineSpace once...` and then failed in `Assert-CandidatePublic` while converting the mask `0xDFFFFFFF` to `UInt32`. A subsequent read-only E4.7.2 probe showed:

- candidate handle `0x01BFFFFE` is present;
- `NV_ReadPublic` succeeds;
- Name matches the frozen WRITTEN=CLEAR expected Name;
- attributes are decimal `262164` (`0x00040014`);
- DataSize is 8;
- original 16 NV Names remain unchanged.

This is evidence that DefineSpace succeeded. The first run failed after creation and before reaching the second confirmation prompt, so no `NV_Increment` was sent by that run.

## Mandatory rules

- Do not rerun `01-create-and-increment.ps1`; it would attempt to define an already occupied handle.
- Do not delete/recreate the candidate as a way to recover.
- Do not rerun any increment operation unless the resume script validates the saved state and asks for its explicit confirmation.
- Preserve `%LOCALAPPDATA%\OfflineAgentBudgetLab\E4.7.3\counter-state.json` and `counter-auth.dpapi.xml`.

## Recovery sequence

1. Run `scripts/00-fix-common-uint32-mask.ps1`.
2. Run `scripts/00-offline-marshalling-self-test.ps1`.
3. Run `scripts/01a-resume-after-define.ps1` once.
4. It verifies saved DefineSpace success, protected auth file, the exact candidate Name and attributes, the original 16 Names, and counts (17 NV indexes / 5 counters).
5. Only after all checks pass does it prompt for one `TPM2_NV_Increment` confirmation.
6. If increment succeeds, it verifies WRITTEN=SET, reads and records the actual counter value, and records `ReadyForRebootVerification`.
7. Perform a normal Windows restart, then use the existing `02-verify-after-reboot.ps1`.
8. Cleanup only after persistence verification, using the existing `03-cleanup.ps1`.

If the resume script reports an uncertain increment outcome, do not retry. Use the existing recovery capture procedure and inspect the TPM state.

## Patch detail

`TPMA_NV.WRITTEN` is bit 29. To clear only that dynamic bit when comparing stable attributes, the mask is `0xDFFFFFFF`. PowerShell may parse this hexadecimal literal as a signed `Int32`, so the helper now constructs it explicitly via `Convert.ToUInt32('DFFFFFFF', 16)`. This changes only local response-validation logic; it does not alter the TPM public attributes or command bytes.

The recovery script never invokes `TPM2_NV_DefineSpace`.
