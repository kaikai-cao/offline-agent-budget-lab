## 2. Frozen protocol invariants

For one immutable global budget epoch, let:

- `G` be the global quota limit;
- `Q_i` be the immutable quota reserved by Lease `i` at registration;
- `U_i` be the committed usage attributed to Lease `i`;
- `C0` be the counter baseline for the epoch;
- `C` be the observed global counter value;
- `A = SUM(Q_i)` and `S = SUM(U_i)`.

Required invariants while the Broker is `READY` and no pending intent is being settled:

```text
A = SUM(Q_i)                    and A <= G
0 <= U_i <= Q_i                for every registered Lease i
S = SUM(U_i)                    and S = C - C0
0 <= S <= A <= G
```

All participating Gateway/Broker processes use the same global budget epoch, Issuer trust key, SQLite journal, counter state, counter lock and Broker lock. Every operation ID is global to the epoch and bound to one Lease Grant and one request digest. Exact replay returns the original committed receipt; conflicting reuse is rejected.

Reservations are made at Lease registration. Expiry and revocation block new operations but do not refund reservations. An already durable pending/committed operation may only be settled or replayed against its exact persisted Lease, Grant digest, operation ID and request digest. That recovery path does not reactivate the Lease or authorize new consumption.

The 83-test Execution Binding suite includes the 4 D8.3 adversarial tests:

1. completed execution metadata survives Gateway reconstruction;
2. two Leases racing the same operation ID cannot charge twice;
3. exhaustion of one Lease does not block another active Lease;
4. an exact already-committed operation can be recovered after revocation and expiry, without authorizing new work.

The 39-test Global Budget suite includes registration and reservation races, per-Lease/global quota enforcement, receipt replay and operation binding, thread and independent-process sequence allocation, crash recovery, revocation/expiry, configuration drift, and accounting-integrity checks.

## 4. Explicit trust assumptions and non-goals

The frozen model assumes cooperating processes on one host and a trusted Gateway, Issuer, Broker executable, OS locking implementation and local storage domain. It intentionally does not claim protection against an attacker able to control the host kernel/administrator or replace all relevant code and state together.

The counter is a JSON-file emulator. The model does **not** implement or validate:

- TPM NV counter commands, TPM authorization policy, TBS transport, NV durability, TPM attestation or exclusive hardware counter ownership;
- TEE isolation, hostile-kernel resistance, remote attestation or protected key custody;
- multi-host/distributed locking, consensus, online revocation delivery or cross-host recovery;
- quota refund/reclamation after expiry or revocation;
- arbitrary external-service exactly-once effects. A real tool must provide an enforceable idempotency key or authoritative operation lookup; otherwise uncertain recovery must remain fail-closed/`INDETERMINATE`;
- formal verification, cryptographic protocol proof, production certification or a complete real-world threat analysis.

A Gateway-signed execution receipt is the Gateway's signed statement about the verified Grant, modeled budget receipt, request and tool result. It is not a TPM quote and does not prove that hardware executed a specific NV command.

## 5. Freeze policy and next-stage boundary

D8.0–D8.4 are frozen as the **Offline Global Budget software-model baseline**. No additional feature work should be added to this frozen scope. Any future change to the frozen protocol, accounting, recovery, adapter or receipt semantics must be treated as a new, explicitly scoped stage with:

1. a stated invariant or threat-model reason;
2. a narrowly scoped implementation change;
3. adversarial tests covering the changed boundary;
4. both package regression suites rerun;
5. a new commit and updated evidence record.

Online coordination is a separate future stage. It must preserve the frozen offline invariants or explicitly document and test any proposed protocol change; it is not part of this freeze.
