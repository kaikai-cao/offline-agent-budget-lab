# D8.2 — Global Multi-Lease Budget / Execution Binding Integration

## Objective

Connect the D8.1 `GlobalBudgetBroker` to the existing E4.8.3 `ExecutionBindingGateway` without changing the legacy single-Lease execution path.

The integration uses one shared Global Budget Broker, one SQLite global journal, one counter domain and one cross-process Broker lock. A trusted control-plane adapter binds each E4.8.3 signed execution Grant to its matching D8.1 signed Global Lease Grant.

## Grant pairing

The Issuer signs two related objects:

- E4.8.3 execution Grant: binds subject, audience, context, tools/schema, validity and (for v2) parent authorization / operation ID.
- D8.1 Global Lease Grant v3: binds the same common authorization fields plus `global_budget_id` and the Lease quota.

`GlobalBudgetExecutionAdapter.bind_lease()` verifies both signatures using the same Issuer public key and requires the shared fields to match exactly: Issuer, grant ID, Lease ID, nonce, quota, validity interval, audience, subject, context digest and sorted tool/schema permissions. It then registers the Global Lease and pins the exact E4.8.3 grant digest to that Global Lease digest.

The Gateway does not accept a caller-supplied global Lease ID. It resolves the mapping by the exact signed E4.8.3 `grant_digest`.

## Execution flow

1. `ExecutionBindingGateway` verifies the E4.8.3 Grant as before.
2. The adapter resolves the exact E4.8.3 grant digest to a pre-registered active D8.1 Global Lease Grant.
3. The global budget ID and Global Lease Grant digest are included in the request digest and execution journal operation binding.
4. Gateway budget allocation calls `GlobalBudgetBroker.consume(global_lease_grant, operation_id, request_digest)` through the adapter.
5. The global receipt sequence is exposed as the execution `budget_counter_value`; the signed Gateway execution receipt additionally records `global_budget_id`, `global_sequence`, `lease_used_count` and `global_lease_grant_digest`.
6. A crash after global allocation replays the same Global Budget receipt. A crash after `BUDGET_CONSUMED` recovers metadata from the Execution Journal without consuming twice.

## Invariants preserved

- Sum of Lease reservations does not exceed the global quota.
- A Lease cannot consume beyond its own quota.
- All Lease consumption shares one global counter sequence and Broker lock.
- One operation ID remains bound to one Lease, request digest and signed execution Grant.
- Revoked, expired, unregistered or unbound Leases fail before execution or budget allocation.
- Legacy E4.8.3 single-Lease Broker behavior and D7 identity digests remain compatible.
